# 소수 분주기의 carry 처리 누락 수정

[README](../../README.md#troubleshooting) · [English](./02-fractional-divider-carry.md) · [이전: 공용 Clock Generator](./01-shared-clock-generator.ko.md) · [다음: 입력 클록 변경](./03-source-clock-frequency.ko.md)

## 문제와 조사 과정

개발 중 230,400 bps 이상에서 정상적이지 않은 문자가 반환되는 현상을 확인했다. Hardware Monitor에서 내부 RX 출력부터 데이터가 잘못되어 있음을 확인해 수신부로 조사 범위를 좁혔다. 이후 시뮬레이션 파형에서 트리거 타이밍이 기준 시점과 점차 어긋나는 것을 발견했다.

시험한 설정에서 소수 누산기의 carry는 **입력 클록 한 주기 동안만 High인 펄스**로 발생한다. 이 펄스가 `int_acc == 0`인 시점과 겹치면, 기존 코드는 carry를 반영하지 않고 `div_int`를 재로드했다. 다음 사이클에는 펄스가 사라지므로 해당 소수 분주 보정이 누락됐다.

보정이 누락될 때마다 필요한 대기 한 사이클이 빠졌다. 이 현상이 반복되면서 생성 주기가 짧아지고 타이밍 오차가 누적됐다.

## 수정

카운터가 0인 분기에서도 carry에 따른 한 사이클의 대기를 반영하도록 수정했다.

```systemverilog
if (int_acc == 0)
    int_acc <= frac_carry ? '0 : div_int;
```

Carry가 High이면 카운터를 0으로 유지하고, 펄스가 끝난 뒤 재로드한다. 함께 변경한 출력 로직은 카운터가 0에 진입할 때만 출력을 토글해, 0을 유지하는 동안 추가 토글이 발생하지 않도록 했다. 두 변경은 `b7ba1cb` → `ab0663d`에 포함되어 있다.

> 설계 비교를 위해 작성·측정한 자료. [RTL, 시험 조건 및 원시 결과](../../UART/experiments/clock_generator/README.md).

카운터 동작만 분리한 비교 모델에서 수정 전후의 재로드 로직에 한 사이클의 carry 펄스를 입력했다. 입력 클록 50 MHz, `div_int = 5` 조건에서 기존 카운터는 즉시 5를 재로드했고, 수정한 카운터는 0을 유지했다. 수정 후 다음 0 도달 시점은 **입력 클록 한 사이클인 20 ns만큼 늦어져** 보정이 반영됐다. Carry가 없는 조건과 카운터가 0이 아닐 때 carry가 발생하는 대조 조건에서는 두 모델이 동일하게 동작했다.

## 검증 결과

실제 수정 전후 분주기 RTL에서도 각 소수 누산기가 생성하는 carry를 확인했다. 아래 각 설정에서 1.1 ms 동안 관찰한 carry는 모두 한 사이클 길이였다. 카운터 0과 carry가 겹친 모든 시점에서 기존 로직은 carry를 무시했고, 수정한 로직은 보정을 반영했다.

50 MHz 조건은 이후의 입력 클록 변경과 분리해 carry 수정 효과를 확인하기 위한 것이다. 추가로 프로젝트의 최고 전송 속도인 **60 MHz / 921,600 bps** 조건도 확인했다. 주파수 오차는 동일한 RX 로직과 독립적인 기준 타이밍을 사용한 기존 10 ms UART 코어 시험에서 측정했다.

  <img src="../img/troubleshooting/02-phase-error.png" alt="분주기 전체 수정 전후의 누적 타이밍 오차" width="900">
</p>

| 입력 클록 (MHz) | 전송 속도 (bps) | 수정 전 carry 누락 횟수 / 1.1 ms | 수정 전 주파수 오차 | 수정 후 주파수 오차 |
| --- | ---: | ---: | ---: | ---: |
| 50 | 230,400 | 2,048 | +4.2117% | +0.0016% |
| 50 | 460,800 | 2,240 | +4.6083% | +0.0016% |
| 60 | 921,600 | 14 | +0.0251% | +0.0049% |

수정한 분주기는 이 시험에서 **카운터 0과 겹친 carry의 보정 누락이 0회**였고, 평균 주파수 오차 ±0.1% 기준을 만족했다. 잡음 없는 세 가지 UART 코어 시험에서는 수정 전후 모두 RX와 TX 각각 72/72바이트가 일치했으며, 누락·추가 수신·시간 초과는 없었다.

이번 비교에서는 carry 누락과 누적 타이밍 오차를 직접 확인했다. **당시의 문자 오류 자체는 재현하지 못했으며**, 해당 증상은 개발 당시의 경험으로 구분해 기록했다. 최고 전송 속도에서도 50 MHz의 두 조건보다 측정 오차가 작았으므로, 이 문제의 심각도를 전송 속도만으로 판단할 수는 없다.

Carry 처리만 변경한 모델과 같은 시기에 변경된 RX 샘플링 위치의 대조 시험 결과도 원시 자료에 보관했다. Carry 처리만 변경하면 추가 출력 토글이 발생했고, 샘플링 위치 대조 시험은 두 조건 모두 통과했다. 이 결과는 핵심 원인인 한 사이클 carry 누락과 구분했다.
